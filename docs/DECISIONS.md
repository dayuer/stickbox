## 2. 硬约束

- 板子无 PSRAM：稳态空闲堆 ≥110KB，取帧最低 ≥40KB。任何新增常驻内存都要给出实测数。
- 已发布的 v1.0.0 固件还在线：服务端协议改动必须向后兼容（ETag 用数字串、MQTT 消息 ≤1024B、`X-Frame-Version` 保持数字串且 ≤12 字节、`ver` 字段保留且等于主主题版本）。
- 三星电视：SOAP 里只转义 `& < >`；MJPEG 最大 1080p。
- 板子和电视是共享资源：只有集成会话调度上板，开发会话不得自行刷板、停推流。

## 4. 协作规则

1. 一个会话一个 worktree，建在 /tmp 或兄弟目录，合并后自己删。
2. 分支只推 `task/*` 或 `fix/*`，**不推、不合并 main**；做完发"分支名 + 提交号 + 一段摘要 + 测试结果"。
3. 固件构建一律在 `git archive` 导出的 /tmp 目录里做，不在用户的主 worktree 里（那里有指向旧服务器的本地 `cloud_creds.h`）。
4. 每个任务在**开工前**回报理解和范围（一句话即可），在**关键节点**（协议定稿、第一次上板前、改动超过原范围时）先回报再继续。
5. 发现需求和本文档冲突、或者要改别人目录，**停下来问集成会话**，不要自己裁决。
6. 不要为了让测试通过去改测试期望；不要顺手重构范围外的代码。
