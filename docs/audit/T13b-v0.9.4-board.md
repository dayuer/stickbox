# T13b v0.9.4 上板验收（2026-10-17，task/T13b-frame c45f07d）

结论：**不通过**。两个阻塞项修完后出 v0.9.5 再上板。

## 通过
- 冷启动到电视出真实看板 **11.6 s**（6.4 s 电视拉流显示状态页 → 10.4 s 开始取帧 → 11.6 s 新帧上屏），目标 <15 s
- 起播 burst 8 帧 0.5 s；之后 2 fps 稳态（60 s 114 帧），无断流
- 服务端帧未变时 304 不重拉；flash 里有帧时开机直接用它起播
- 主机侧：SBF1 容器 → 解析 → 拼接，与服务端 frame.Bundle.Splice 在 00:00 / 08:28 / 12:47 / 23:59 逐字节一致（08:28 带长 13,089 = max_band_bytes）

## 阻塞 1：配对后被踢线，重连 TLS 配置丢失，永远连不上
```
E esp-tls-mbedtls: No server verification option set in esp_tls_cfg_t structure
E esp-tls-mbedtls: Failed to set client configurations, returned [0x8017] (ESP_ERR_MBEDTLS_SSL_SETUP_FAILED)
E cloud: MQTT 错误 type=1 → 33 s 后重连 → 同样错误 → 64 s 后 …
```
场景：pending 设备配对成功 → 服务端 KickDevice → 设备重连。疑为转正/配对后 `esp_mqtt_set_config` 或重建 client 时漏了 `crt_bundle_attach`。
验收必须包含「配对 → 被踢 → 重连成功 → 收到 paired=true → 取帧」。

## 阻塞 2：堆历史最低 14,380 / 21,196 字节；稳态 79–98 KB（v0.9.3 为 142 KB）
- 开机取帧被触发 3 次（开机 + 服务端两次 v9 通知），TLS 叠加。要求：同一版本只拉一次；取帧进行中收到通知只置标记；通知版本 = 正在取/已激活版本直接忽略
- 稳态少约 45 KB，需 memdiag 对账（2×16K 带缓冲、时钟任务 4096、取帧任务是否常驻）
- 目标：取帧期间历史最低 ≥ 40 KB，稳态 ≥ 110 KB

## 服务端配合问题（esp1 修）
CLI `device unbind` 不踢旧连接 → 设备重新注册的 pending 连接被防顶号误拒 → 「注册 → 被拒 → 清密钥 → 重启」循环。
修法：admit 判断「同 dev 有非 pending 在线连接」时实时核对该连接密钥是否仍有效；CLI 解绑/吊销也踢线。
