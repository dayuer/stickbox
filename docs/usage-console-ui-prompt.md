## 提示词

设计一块 **240×240 像素的方形小屏 UI**，显示在 1.3 寸 ST7789 TFT LCD 上（ESP32-S3 板载屏，RGB565 色彩，实际物理尺寸约 23mm×23mm，桌面上 40–60cm 距离观看）。用途：**一眼看清 Claude 订阅的用量消耗情况**，像一块桌面仪表。

### 当前版面（自上而下，坐标为像素）

**纯黑背景（#000000）**，内容区 234×234（右、下各留 6px 给防烧屏的整屏位移）。

1. **标题栏**（y 0–22，整条深蓝灰底 #16202A）

   - 右（右对齐）：设备 IP `192.168.3.14`，灰 #7A8896，16px

2. **「5 小时」窗口卡片**（y 28–104）
   - 第 1 行（y 28）：左 `5 小时`（浅白 #F0F0F0，16px）；右对齐 `4时16分后重置`（灰 #7A8896，16px）
   - 第 2 行（y 46）：左侧超大百分比 `2%`，Montserrat 40px，颜色随状态变化（见下）
   - 大数字右侧（x 118 起）两行小字：

### 状态与颜色逻辑

每个窗口独立判定，**大百分比、预测文字、进度条填充同色**：

| 状态 | 条件 | 颜色 | 预测文字 |
|---|---|---|---|
| 安全 | 按当前平均速度能撑到重置 | 绿 #3DDC84 | `够用到重置` |
| 超速 | 按当前速度会在重置前用完 | 琥珀 #FFB020 | `约X用完`（如 `约4天7时用完`） |
| 危险 | 已用 ≥ 90% | 红 #FF5A5A | 同上 |
| 用满 | 100% | 红 | `已用满` |
| 刚开始 | 窗口时间过去 < 5% | 绿 | `够用到重置`（数据太少不预测） |
| 已重置 | 过了 resets_at、还没收到新数据 | 灰 | 大字 `--`，右上 `已重置`，预测 `等新数据`，进度条清空、竖线隐藏 |
| 无数据 | 开机后还没收到过上报 | 灰 | 大字 `--`，预测 `等待数据`，页脚左 `POST /api/usage` |

**核心读法**：进度条（用量）在白竖线（时间）**左边**＝用得比时间慢、安全；**越过竖线**＝超前消耗。

### 动态行为

- 每秒刷新：倒计时、时间过去百分比、预测、「更新 X前」都按本地时钟走，两次上报之间也在动
- 数据每 10 分钟由电脑推一次（`POST /api/usage`）
- 防烧屏：每 2 分钟整屏沿 3px 步长的小方框位移一格；5 分钟无新数据背光降到 12%，来数据恢复 100%
- 时间格式：≥1 天 `X天Y时`，≥1 小时 `X时YY分`，否则 `X分`

### 技术约束（重新设计时必须遵守）

- **字体**：中文只有一套 16px 黑体（GB2312 一级字库 + ASCII + `，。：、！？（）《》—…·％`），**不能用一级字库以外的汉字和 emoji**；拉丁/数字另有 Montserrat 14px 和 40px，可再开 Montserrat 其它字号（8–48 偶数）
- **渲染**：LVGL 9，单缓冲 240×16 行，SPI 刷屏；避免大面积渐变、透明叠加、阴影、频繁整屏动画
- **TFT LCD 不是 OLED**：黑色不省电（背光常亮），但深色底更不刺眼；大块静态高亮要少，配合位移防残影
- **可用数据**：每个窗口只有 `used_percentage`（0–100）和 `resets_at`（Unix 秒）两个数；另可得设备 IP、上次更新时间。服务端 `/usage` 报告里还有 `weekly_scoped`（按模型的周用量）和 `extra_usage`（超额额度）行，目前没接，需要的话可以加
- **无触摸、目前无按键交互**：板子有 4 个物理按键（OK / UP / DOWN / MENU），可以设计成切页。其中 MENU 开机时按住会清空 Wi-Fi 配置，OK 兼作 BOOT 键，这两个只适合在运行时使用

### 当前设计的不足（供重新设计参考）

- 信息密度高、字小，40cm 外只能看清两个大百分比
- 两块卡片完全对称，看不出哪个窗口是当下更要紧的
- 「时间过去 X%」和竖线表达同一件事，重复
- 页脚「会话 --」是无效信息
- IP 常驻标题栏占了显眼位置，只在配置时有用
