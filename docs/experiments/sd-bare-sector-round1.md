# microSD 裸扇区实验 · 第一轮（2026-10-18，实机）

固件：esp 的 sdtest 实验构建（v0.9.5-sdtest，sha256 c406a637…），板子 ESP32-S3-USB-OTG，256GB microSD。
实验区：卡末尾 1MB；其余只读。

## 结果

| 项 | 结果 |
|---|---|
| 接口 | SDMMC 4-bit，40MHz，初始化成功，容量识别正常 |
| 引脚 | D0–D3=37/38/33/34，CMD/CLK=35/36；与 USB OTG、LCD、按键无重叠 |
| 单次读 240KB（8KB 块） | 约 34ms |
| 持续读 | 约 900KB/s，失败 0；同时推流 +65 帧/32s（≈2fps，不中断） |
| AVI 从 SD 分块推真实电视 | PLAYING 连续 3 分钟不断，画面正常（用户肉眼确认） |
| 拔卡/插卡 | 板子不崩不重启（读失败是否被触发未证实） |
| **初始化堆增量** | **≈21.4KB**（112148→90724，含 8KB 读缓冲）；目标 ≤10KB，**未达标** |
| **读卡 + 取帧 TLS 并发时堆历史最低** | **10,332 B**；目标 ≥40KB，**未达标，危险** |
| 掉电恢复 | 模拟中断（只写数据不写头）扫描正确；真实拔电窗口只有 20 秒，**未测** |

## 结论与约束

- 读速、推流、电视兼容都没问题；问题全在内存。
- 在第二轮证明"挂载状态下整体最低堆 ≥40KB"之前，**不得假设读卡可与取帧 TLS 并发**。
  照片流程按互斥设计：联网取清单/下载 → 写卡 → 卸载 → 本地读卡推流。
- 第二轮待办（esp）：10,332 的来源分析、1-bit 对比、挂载与取帧互斥后的堆、60 秒拔电窗口、读缓冲复用/缩到 4KB。

# 后续轮次（2026-10-18，实机，用户真实照片）

## 结论
- **整条链路跑通**：用户照片（4032×3024 → 缩成 1920×1080，剥掉 EXIF/GPS，228,024 B）经局域网 POST 写入 SD 卡裸扇区 → 写后读回校验通过（crc eea4eacb，头尾 16B 一致）→ 卸载 → 电视拉 `/sdphoto.avi`，板子每帧按 4KB 从卡里读、写 00dc、send_all，**电视上画面清晰（用户确认）**。
- 内存（互斥：上传/读卡期间暂停取帧）：驱动本体约 2.7KB，4-bit+8KB 缓冲合计约 10.6KB，4-bit+4KB 约 6.8KB；上传时挂载后空闲约 61KB，卸载后约 93KB。sd_avi 任务栈 10KB，余量 5–7KB。
- 读速：8KB 块单次约 8.3MB/s，持续 2fps 约 480KB/s，失败 0；4KB 块同样够用。

## 踩到的坑（必须写进正式实现）
1. **掉电会让卡对板子不可用**：真实拔电后这张卡对板子一直初始化超时/CRC 错误（重插、全断电都没用），在 Mac 上重新格式化后恢复。卡不可用时看板必须照常，并上报状态。
2. **recv 长度不固定**：写扇区偏移必须只用"已落盘字节数"，不能用"已收字节数"（round-4 因此把数据写错位）。**必须做写后读回校验**，失败不得返回成功。
3. 上传/读卡任务栈 4KB 会溢出，至少 10KB。
4. 实验固件里板子的看板监督逻辑会在电视不拉自己的流时 20 秒后把屏幕抢回去；正式实现里照片模式需要告诉监督逻辑"当前在播照片"。
5. 下载与读卡必须互斥（取帧 TLS 与挂载不并发）。
